# M0 – Skeleton, contracts, seams, CI (`m0-skeleton`)

Shared by Person A and Person B. Built by Person A; `m0-skeleton` is tagged on main after this PR merges.

**Built**
- Maven project with wrapper (Maven 3.9.11), Java 21.
- Versions: Spring Boot **4.0.9** with the Spring AI **2.0.2** BOM. They resolved together, so the
  3.5.x / 1.1.x fallback was not needed. Jackson is 3.x (`tools.jackson`), MCP Java SDK 2.1.0.
- Dependencies: web, security, validation, actuator, `spring-ai-starter-mcp-server-webmvc`, test, security-test.
- `application.yml`: port 8080, MCP server `aida` 0.1.0 with STREAMABLE protocol at `/mcp`, AIDA settings
  (jira/leave base URLs, tokens file, data dir, alerts), profile `mock` on by default.
- All contract records in `com.aida.contract` plus a `Statuses` helper (workflow order, active, client-side).
- Fixtures in `src/test/resources/fixtures`: 15 SHOP issues (every status, epics SHOP-E5 and SHOP-E7, one story
  without an estimate, SHOP-106 in Waiting for Client UAT for 8 days at 2026-10-27), the 6-person SHOP team,
  2 leaves and 2 public holidays.
- `.github/workflows/ci.yml`: checkout, Temurin 21 with Maven cache, `./mvnw -B verify` on every push and PR.

**Seams (FROZEN signatures; bodies throw `UnsupportedOperationException` until their milestone)**

| Seam | Shape | Implemented in |
| --- | --- | --- |
| `adapter.JiraSource` | `issues(project, release /* null = all */)`, `releases(project)` | A2 (`HttpJiraSource`) |
| `adapter.LeaveSource` | `team(project)`, `absences(from, to)` | A2 (`HttpLeaveSource`) |
| `engine.Snapshots` | `static snapshot(issues, d)` | B1 |
| `engine.Capacity` | `static byWeek(team, absences, start, weeks)` | B2 |
| `engine.ForecastEngine` | `forecast(issues, release, asOf, team, absences, targetDate, runs, seed)` plus an overload with `DEFAULT_RUNS` 10,000 and `DEFAULT_SEED` 42 | B2 |
| `engine.QualityEngine` | `assess(issues, asOf)` | B3 |
| `engine.ExplainEngine` | `explain(issues, release, fromDate, toDate, team, absences)` | B4 |
| `engine.WhatIfEngine` | `run(issues, release, asOf, team, absences, whatIf)` | B4 |
| `engine.RiskEngine` | `assess(issues, asOf)` | B4 |
| `engine.ReportEngine` | `build(issues, release, asOf, team, absences, audience)` | B5 |
| `mock.DataGenerator` | `static generate(asOf, seed)` → `mock.Dataset(issues, versions, team /* by project */, absences)` | A1 |
| `mcp.AidaToolSet` | marker interface; every `@Tool` class implements it and is a `@Component` | – |
| `mcp.ToolConfig` | registers all `AidaToolSet` beans as MCP tools; also exposes each engine as a bean | – |
| `mcp.ToolSupport` | `call(tool, project, args, body)` → result as a JSON object plus `meta {tool, calledAt, windowStart, windowEnd}`; stub has no access check or audit | A3 |
| `mcp.ProjectData` | `@Component` with `load(project, asOf)` → `ProjectData.Data(issues, team, absences, releases)` | A2 |

Notes for both tracks:
- Engines other than `Snapshots`, `Capacity` and `DataGenerator` are plain stateless classes with instance methods,
  exposed as beans in `ToolConfig`, so tool tests can replace them with `@MockitoBean`.
- `ToolSupport.call` returns `Map<String, Object>`; tool methods return that map so Spring AI serialises it once.
- `ProjectData.load` returns the nested record `ProjectData.Data` because `ProjectData` itself is the loader bean.

**Tests**
- `ContractJsonTest`: JSON round trip for every record, ISO dates, contract field names.
- `FixturesTest`: fixture shape (every status, 2 epics, one missing estimate, 8-day UAT wait, team, absences).
- `AidaApplicationTests`: context loads; the application's mapper writes ISO dates.
- `SeamsTest`: an `AidaToolSet` bean shows up as an MCP tool; `ToolSupport` adds the meta block with the data window.

**Known gaps / notes**
- The local network intercepts TLS. Java needs `MAVEN_OPTS=-Djavax.net.ssl.trustStoreType=Windows-ROOT`, and
  Git Bash's curl fails the revocation check on the intercepting CA, so locally the build runs via `mvnw.cmd`
  (PowerShell download). CI on GitHub's Linux runners uses `./mvnw` directly.
- Spring Security still uses its generated default user; bearer-token security lands in A3 (M4).
- Branch protection on main is not set: the GitHub account `tlanhlua` has write but not admin rights.
  The repository owner has to apply it (command in Person A's prompt, step 3).
